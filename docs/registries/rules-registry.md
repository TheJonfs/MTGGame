# Rules Registry

R-numbered entries describing which Comprehensive Rules mechanics the engine implements, how, and any simplification. Implementer appends; planner reviews. Cite CR section where known. Status: `implemented` / `slot-only` / `planned` / `excluded`. `(interim)` marks a deliberate simplification awaiting planner ratification.

| R-001 | Turn structure & steps | 500–514 | implemented (S1) | All steps present. First-strike step only runs when a first/double striker is in combat. Declare blockers/damage steps skipped when no attackers (508.8). Cleanup: no priority unless triggers are pending (S1 has no cleanup triggers; general path exists). |
| R-002 | Priority | 117 | implemented (S1) | APNAP; both pass on empty stack advances step; acting player retains priority (117.3c); SBAs + trigger placement before every priority grant (117.5). A lone legal `pass` is auto-taken and not logged (deterministic; see R-029). |

| R-006 | Mana & auto-payment | 106, 601.2g | implemented (S3: + {C}) | Auto-pay (ADR-004 amended): cast legal if floating + untapped producers cover; colored shortfalls tapped first; generic deducted {C}-first then WUBRG ({C} spends nowhere else, so this greedy is optimal). | R-007 | SBAs | 704 | implemented (S5: choice SBAs live) | One routine, looped; one pass applies simultaneously. | R-008 | Combat steps | 506–511 | implemented (S2) | Assignment and dealing are separate functions (ADR-006). Multi-blocker damage order chosen by the attacker via orderBlocker actions (509.2, ADR-011) — S1 interim retired. |

| R-011 | Haste / summoning sickness | 302.6 | implemented (S5: control-change note closed) | Sickness set on battlefield entry, cleared at controller's untap, and re-set on every control change in either direction (syncControl, ADR-033). Control Magic exercises steal and reversion. |
| R-012 | Vigilance | 702.20 | implemented (S1) | No tap on attack declaration. |
| R-013 | Trample | 702.19 | implemented (S2) | Pure assignment rule, as the manifest's litmus test demanded: lethal (toughness minus marked damage) per blocker in order, excess to the defending player. |
| R-014 | Deathtouch / lifelink | 702.2 / 702.15 | implemented (S3) | Exactly the two ADR-006 slots: deathtouch makes 1 lethal in assignment (510.1c, source's deathtouch) and marks dealt damage for the SBA destroy (704.5h, honors indestructible); lifelink gains on dealing, combat and noncombat alike, simultaneous (702.15f). | R-015 | Menace | 702.110 | implemented (S3) | Aggregate check at commit (0 or ≥2 blockers) plus dead-end-free incremental enumeration: a lone menace block is only offered when a second candidate exists, and while a violation stands only fixing blocks are offered. |
| R-016 | Triggered abilities & APNAP ordering | 603 | implemented (S4: + conditions, damage events) | Collected from ZONE_CHANGE (self conditions) and DAMAGE events (battlefield scan with ADR-021 condition evaluation: `source: self/attached/other`, `player: opponentOfController/controller`, Curiosity). DEALS_DAMAGE_TO_PLAYER (any damage) and DEALS_COMBAT_DAMAGE_TO_PLAYER both live. `controller`/`type`/`subtype` condition fields validated but unexercised until a card needs them. |
| R-017 | Continuous effects / layers | 613 | implemented (S4: + parameterized scopes) | ADR-003 order. Resolved effects stored with timestamps; EOT expire in cleanup; counters after P/T per ADR-003. |
| R-018 | Auras & attachment legality | 303.4, 704.5m | implemented (S1) | Aura spells target; enter attached to targets[0]; SBA sends aura to graveyard when host is illegal or gone. `attached` scope added to the vocabulary's Scope enum for aura/equipment statics. |

Targeted/EOT control (Threaten) reserved. |
| R-021 | Tokens | 111 | implemented (S4: color note closed) | Token defs load from `data/cards/tokens/`; createToken resolver; tokens cease on leaving the battlefield (111.7).
